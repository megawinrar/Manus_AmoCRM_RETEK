# Настройка и запуск микросервиса RETEK amoCRM

Этот документ описывает, как настроить, запустить и перенастроить микросервис автоматизации тендерного процесса RETEK.

## 1. Архитектура микросервиса

Микросервис состоит из следующих компонентов:
* **FastAPI сервер** (`src/microservice/main.py`) — обрабатывает входящие вебхуки от amoCRM
* **APScheduler** — запускает фоновые задачи (cron-джобы) по расписанию
* **amoCRM API Client** (`src/microservice/amo_client.py`) — обёртка над API с поддержкой rate-limit (7 req/s) и автоматическими повторами
* **Модуль конфигурации** (`src/microservice/config.py`) — содержит все правила маршрутизации, маппинг полей и статусов

### Расписание фоновых задач
* **Ежечасно (00 минут):** `cron_hourly.py` — проверяет зависшие сделки приоритетов Р1/Р2 (без задач или с просроченными задачами), а также сделки без заполненного поля «Следующее действие».
* **Ежедневно (в 02:00):** `cron_daily.py` — выполняет автоматическую архивацию сделок из статуса «11. К архивированию» и проверяет даты возврата из архива.
* **Еженедельно (Пн, 09:00):** `cron_weekly.py` — ищет зависшие сделки (>7 дней в одном статусе) и проверяет WIP-лимиты сотрудников.
* **Ежемесячно (1-е число, 08:00):** `cron_monthly.py` — полная ревизия архивов и формирование отчёта.

## 2. Первичная настройка (или перенастройка при смене аккаунта)

Если вы переносите микросервис в другой аккаунт amoCRM или у вас изменились ID воронок, вам нужно пересобрать `.env` файл.

### Шаг 2.1: Создание интеграции в amoCRM
1. Зайдите в amoCRM → **Настройки** → **Интеграции** (или amoМаркет → Установленные).
2. Нажмите **Создать интеграцию** → **Внешняя интеграция**.
3. Укажите права доступа: `Доступ к данным CRM`, `Управление задачами`, `Управление уведомлениями`.
4. В поле Redirect URI укажите любой валидный URL (например, `https://example.com/callback`).
5. Сохраните. Вы получите **Секретный ключ (client_secret)** и **ID интеграции (client_id)**.

### Шаг 2.2: Получение токенов
Есть два пути получения токенов:

**Путь А: Долгосрочный токен (рекомендуется)**
В настройках созданной интеграции перейдите во вкладку «Ключи и доступы» и нажмите **«Сгенерировать токен»**. Скопируйте его — это готовый `access_token`, который не протухает.

**Путь Б: Через Authorization Code**
Скопируйте «Код авторизации» (действителен 20 минут) и используйте скрипт `src/get_tokens.py`, вставив туда код.

### Шаг 2.3: Запуск скрипта автоматического сбора ID
Откройте файл `src/get_tokens.py` и впишите туда свои:
* `DOMAIN` (например, `tokutools.amocrm.ru`)
* `CLIENT_ID`
* `CLIENT_SECRET`
* `LONG_LIVED_TOKEN` (если используете Путь А)

Запустите скрипт:
```bash
python3 src/get_tokens.py
```
Скрипт подключится к amoCRM, скачает все ID воронок, статусов, пользователей и кастомных полей, после чего сохранит их в файл `amo_data.json`.

### Шаг 2.4: Заполнение .env
Скопируйте `.env.example` в `.env` и заполните его данными из `amo_data.json`.
Обязательно проверьте, что ID пользователей (`USER_EMPLOYEE_2`, `USER_EMPLOYEE_3`, `USER_MANAGER`) указывают на правильных сотрудников.

## 3. Настройка правил маршрутизации и бизнес-логики

Вся бизнес-логика хранится в файле `src/microservice/config.py`. Если бизнес-процесс меняется, вам нужно редактировать только этот файл.

### Изменение правил создания задач при смене статуса
Ищите словарь `STATUS_TASK_RULES`. 
Например, чтобы изменить текст задачи при переходе в статус «СОЗ — звонок»:
```python
"SOZ_CALL": {
    "text": "Позвонить клиенту, уточнить потребность и сроки",
    "responsible": "EMPLOYEE_2_SALES",
    "deadline_seconds": 24 * 3600,  # 24 часа на выполнение
    "task_type_id": 1,  # 1 = Звонок
}
```

### Изменение маршрутизации из LLM
Ищите словарь `ROUTING_RULES`.
Формат: `("Приоритет", "Тип ситуации"): ("СТАТУС", "ОТВЕТСТВЕННЫЙ")`

```python
ROUTING_RULES = {
    ("Р1", "СОЗ"): ("SOZ_CALL", "EMPLOYEE_2_SALES"),
    ("Р1", "Запрос котировок / реальные торги"): ("PURCHASING", "EMPLOYEE_3_BUYER"),
    # ...
}
```

### Изменение правил архивации
Ищите словарь `ARCHIVE_ROUTING`. Он связывает значение поля «Архивное назначение итоговое» с конкретной воронкой и статусом архива.

Ищите список `ARCHIVE_REQUIRED_FIELDS` — здесь перечислены поля, которые ОБЯЗАТЕЛЬНО должны быть заполнены перед тем, как микросервис разрешит перенос сделки в архив.

## 4. Запуск микросервиса

### Локальный запуск (или на сервере без Docker)
Установите зависимости и запустите uvicorn:
```bash
pip install -r requirements.txt
uvicorn src.microservice.main:app --host 0.0.0.0 --port 8000
```

### Запуск через Docker
```bash
docker build -t retek-amocrm .
docker run -d -p 8000:8000 --env-file .env --name retek_microservice retek-amocrm
```

### Тестовый режим (DRY RUN)
В файле `.env` есть параметр `DRY_RUN`.
* `DRY_RUN=1` — микросервис работает, читает данные, логирует свои решения, но **НИЧЕГО НЕ МЕНЯЕТ** в amoCRM (не создаёт задачи, не двигает сделки). Идеально для отладки.
* `DRY_RUN=0` — боевой режим.

## 5. Настройка вебхуков в amoCRM

Чтобы микросервис мгновенно реагировал на смену статусов, нужно настроить вебхук в amoCRM:
1. Зайдите в **Настройки** → **Интеграции** → **Webhooks**.
2. Добавьте URL вашего запущенного микросервиса: `https://ваш-домен.com/webhook`
3. Отметьте галочками события:
   * Смена статуса сделки
   * Добавление сделки (опционально, если нужно обрабатывать новые)
4. Сохраните.

Теперь при любом перемещении сделки amoCRM будет отправлять POST-запрос в микросервис, а он будет мгновенно создавать задачи согласно правилам из `config.py`.

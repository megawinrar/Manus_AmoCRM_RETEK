# RETEK amoCRM — Полный контекст проекта

## Бизнес

Тендерная компания RETEK — торгует режущим инструментом на тендерных площадках.

## Платформа

amoCRM (внешняя интеграция, не приватная).

## Главная логика

LLM распознаёт файлы → создаёт/обновляет сделку amoCRM → сделка попадает в активную воронку → сотрудники двигают её по процессу → финальные карточки уходят в статус "К архивированию" → внешний микросервис переносит их в архивные воронки.

## Основная воронка: Тендеры RETEK — активная работа

Статусы (по ТЗ из документации):

```
1.  LLM распознал
2.  Проверка Сотрудника 2
3.  СОЗ — звонок / уточнить дату
4.  СОЗ — ждём реальный торг
5.  Передано в закупку / расчёт
6.  КП готовится
7.  КП передано дилеру
8.  Решение дилера
9.  Передано в производство
10. К архивированию
```

## Маршрутизация

```
Р1/Р2/Р3 + СОЗ → Сотрудник 2 / продажник / квалификатор
Р1/Р2/Р3 + Запрос котировок / реальные торги → Сотрудник 3 / закупщик / расчётчик
Неясно → Сотрудник 2, может передать Сотруднику 3
Р4 → Наблюдаем / В базу / Архив
```

## Приоритеты

```
Р1 — Срочно
Р2 — Быстрые Деньги
Р3 — Средние Деньги
Р4 — Наблюдаем / В базу
```

## Направления

```
SPEC-DRAWING — специнструмент по чертежам / ТЗ
HSS-STANDARD — стандартный быстрорез / ГОСТ
CARBIDE-STANDARD — стандартный твердосплав
DIAMOND-STANDARD — алмазный инструмент без чертежа / стандартный
SOZ-DEVELOPMENT — СОЗ / развитие / будущий торг
REAL-TENDER — реальные торги / запрос котировок
OUT-OF-SCOPE — не наш ассортимент
ARCHIVE-LEAD — база / наблюдение / будущая проработка
```

## Роли

```
Сотрудник 1 — загрузчик (файлы/ссылки)
LLM — первичный классификатор
Сотрудник 2 — продажник/квалификатор (СОЗ, проверка LLM)
Сотрудник 3 — закупщик/расчётчик (реальные торги, КП)
Сотрудник 4 / дилер — решение о выходе на торги

Микросервис — архиватор (перенос сделок, контроль просрочек)
```

## Правило активной CRM

> В активной воронке живёт только то, по чему есть следующее действие.
> Если следующего действия нет — дата возврата или архив с причиной закрытия.

## Микросервис — функции

```
создать сделку из JSON LLM
обновить сделку
создать задачу
добавить примечание
перенести сделку в другой статус
перенести сделку в архивную воронку
проверить просрочки
создать задачу на дату возврата
```

## amoCRM API лимиты

- 7 запросов/сек на интеграцию
- 50 запросов/сек на аккаунт
- При PATCH статуса — ВСЕГДА передавать name + color + sort вместе (иначе сбрасывает)
- POST статусов принимает массив [{...}]
- Больший sort = левее в Канбан

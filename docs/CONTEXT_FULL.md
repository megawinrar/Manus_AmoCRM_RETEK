# RETEK amoCRM — Полный контекст проекта (PATCH5 CLEAN)

## Бизнес-задача

RETEK — тендерная компания, торгует режущим инструментом (специнструмент по чертежам, HSS/ГОСТ, твердосплав, алмазный) через тендерные площадки. Входящий поток — тендеры и запросы котировок (СОЗ), которые нужно быстро квалифицировать, посчитать и принять решение о выходе.

## Платформа

amoCRM (внешняя интеграция, не приватная).

## Главная логика

LLM распознаёт файлы → создаёт/обновляет сделку amoCRM → сделка попадает в активную воронку → сотрудники двигают её по процессу → финальные карточки уходят в статус "К архивированию" → внешний микросервис переносит их в архивные воронки.

## Роли

| Роль | Зона ответственности |
|---|---|
| Сотрудник 1 / загрузчик | Загружает файлы. Не принимает бизнес-решений |
| LLM | Распознаёт, классифицирует, предлагает маршрут, приоритет, направление |
| Сотрудник 2 / продажник / квалификатор | Владелец входящего потока, проверки LLM, СОЗ. Звонит, уточняет дату |
| Сотрудник 3 / закупщик / расчётчик | Владелец закупки, расчётов, КП, поставщиков, передача КП дилеру |
| Сотрудник 4 / дилер | Принимает решение: выходить на торги или нет |
| Производство 1/2 | Получает заявку после решения дилера |
| Руководитель | Контроль Р1/Р2, просрочки, ревизия архива |

## Расписание микросервиса

```
каждый час — контроль Р1/Р2 и просроченных задач
раз в сутки ночью — перенос в архив
раз в неделю — поиск зависших карточек
раз в месяц — ревизия архива и отчёт руководителю
```

## Правило активной CRM

> В активной воронке живёт только то, по чему есть следующее действие.
> Если следующего действия нет — дата возврата или архив с причиной закрытия.

## Название сделки (формат)

```
[Приоритет] [Тип ситуации] — [Заказчик] — [предмет / группа инструмента] — [ключевое действие]
```

Примеры:
```
[Р2] СОЗ — Протон-ПМ — специнструмент — уточнить дату торгов
[Р1] Запрос котировок — Пермские моторы — сверла — срок 12.06
[Р3] Неясно — завод N — чертежи — проверить СОЗ или торги
```

## amoCRM API лимиты и особенности

```
7 запросов/сек на интеграцию
50 запросов/сек на аккаунт
При PATCH статуса — ВСЕГДА передавать name + color + sort вместе (иначе сбрасывает)
POST статусов принимает массив [{...}]
POST игнорирует sort — назначает автоматически
Больший sort = левее в Канбан
```

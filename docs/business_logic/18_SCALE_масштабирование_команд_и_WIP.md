# Масштабирование команд и WIP

## Проблема роста

При добавлении новых сотрудников нельзя просто дать им доступ ко всей активной CRM. Это создаст хаос.

## Решение

Использовать поля:

```text
Команда
Ответственный продажник
Ответственный закупщик
Направление
Подтип направления
Контролёр
```

## Не дублировать доски

Дублирование досок создаёт проблемы:

```text
разные правила
дубли карточек
сложно сравнивать результаты
сложно контролировать руководителю
теряется единая аналитика
```

## Новые сотрудники получают очередь

```text
СОЗ к обзвону
Р3 к проверке
архив специнструмента
архив по заводам
карточки без следующего действия
```

## Варианты разделения команд

### По сложности

```text
Опытная команда → Р1/Р2 + специнструмент
Новая команда → СОЗ + Р3 + архив
```

### По направлению

```text
Команда 1 → специнструмент по чертежам
Команда 2 → стандартный инструмент / ГОСТ
```

### По типу работы

```text
Команда 1 → активные торги
Команда 2 → развитие / СОЗ / архив
```

## WIP-лимиты на пару

```text
Р1: 3–5 одновременно
Р2: 7–12 одновременно
Р3: 15–25 одновременно
СОЗ ожидание / обзвон: 30–50 одновременно
Р4: не держать в активной воронке
```

## Месячная пропускная способность

Ориентировочно:

```text
лёгкие входящие с хорошим LLM-фильтром: 100–200 / месяц
много расчётов и КП: 40–80 / месяц
много СОЗ: 150–300 / месяц, если СОЗ ведутся как лёгкая отдельная очередь
```

## Правило руководителя

Если на пару висит больше 80 активных карточек, нужно:

```text
архивировать Р4
перенести СОЗ в ожидание
разгрузить закупщика
добавить сотрудника
сократить вход через фильтры LLM
```

# Контекст проекта: RETEK Tender CRM на amoCRM

Проект описывает CRM-процесс для обработки тендеров, СОЗ, запросов котировок, закупок инструмента и работы с дилерами/производством.

## Текущая целевая платформа

**amoCRM**.

Предыдущие версии архива рассматривали Odoo/Airtable как варианты. В PATCH4 рабочая концепция переориентирована на amoCRM, так как текущая задача лучше соответствует канбан-CRM: сделки, статусы, ответственные, задачи, комментарии, воронки и архивные сегменты.

## Философия системы

CRM — это не склад всех найденных закупок.

CRM — это рабочий пульт, который отвечает на вопросы:

```text
Что требует действия сегодня?
Кто отвечает?
Что мешает движению?
Когда вернуться к карточке?
Почему карточка закрыта или архивирована?
```

## Главная сущность

**Сделка amoCRM** = тендерная возможность.

Одна сделка может соответствовать:

```text
СОЗ / сбор КП / предварительная процедура
реальному запросу котировок / идущим торгам
тендеру с несколькими лотами
архивной возможности для будущей проработки
```

Если в закупке несколько лотов с разными направлениями, LLM должен указать смешанность и предложить разделение или основной маршрут.

## Роли

### Сотрудник 1 / загрузчик

Загружает файлы. Не принимает бизнес-решений.

### LLM

Распознаёт документы, извлекает данные, классифицирует, предлагает маршрут, приоритет, направление, архивное назначение.

### Сотрудник 2 / продажник / квалификатор

Владелец входящего потока, проверки LLM и СОЗ. Работает с Р1/Р2/Р3, если это СОЗ. Звонит и уточняет дату реального торга.

### Сотрудник 3 / закупщик / расчётчик

Владелец закупки, расчётов, КП, поставщиков и передачи готового КП дилеру. Получает Р1/Р2/Р3, если это реальные торги / запрос котировок.

### Сотрудник 4 / дилер / канал продаж

Принимает решение: выходить на торги или нет.

### Производство 1 / Производство 2

Получает заявку на основе КП после решения дилера о выходе.

## Приоритеты

Писать строго так:

```text
Р1 — Срочно
Р2 — Быстрые Деньги
Р3 — Средние Деньги
Р4 — Наблюдаем / В базу
```

## Масштабирование

При росте команды не создавать дубли досок без контроля. Использовать поля:

```text
Команда
Направление
Ответственный продажник
Ответственный закупщик
Контролёр / руководитель
```

Новые сотрудники получают не всю CRM, а очередь работы: СОЗ к обзвону, Р3 к проверке, архив по направлению, карточки без следующего действия.

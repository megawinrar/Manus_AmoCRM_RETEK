# Канонические правила LLM-классификатора для amoCRM

## Статус документа

Этот файл заменяет старые обучающие примеры с `crm_status` из Odoo/Airtable-логики.

Файлы старой логики перенесены в `legacy_old_logic/` и не должны использоваться как канонический источник статусов.

## Канонические поля вывода LLM

```yaml
type_situation: СОЗ | Запрос котировок / реальные торги | Неясно | Не наш ассортимент
priority: Р1 — Срочно | Р2 — Быстрые Деньги | Р3 — Средние Деньги | Р4 — Наблюдаем / В базу
direction: SPEC-DRAWING | HSS-STANDARD | CARBIDE-STANDARD | DIAMOND-STANDARD | OUT-OF-SCOPE | ARCHIVE-LEAD
subdirection: строка
active_pipeline_status: один из статусов активной amoCRM-воронки
responsible_role: Сотрудник 2 | Сотрудник 3 | Сотрудник 4 / Дилер | Руководитель
next_action: строка
next_action_date: дата или null
archive_destination_llm: строка или null
confidence: 0.0-1.0
manager_question_required: true | false
```

## Каноническая маршрутизация

```text
Р1/Р2/Р3 + СОЗ → Сотрудник 2 → СОЗ — звонок / уточнить дату
Р1/Р2/Р3 + Запрос котировок / реальные торги → Сотрудник 3 → Передано в закупку / расчёт
Неясно → Сотрудник 2 → Проверка Сотрудника 2
Р4 → К архивированию
Не наш ассортимент → К архивированию
```

## SPEC-DRAWING

`SPEC-DRAWING` объединяет специнструмент по чертежам / ТЗ:

```text
твердосплав по чертежам
быстрорез по чертежам
алмазный по чертежам
прочий инструмент по ТЗ / эскизу / образцу
```

Причина: для CRM это один бизнес-процесс — техническая оценка, расчёт, производство, сроки, коммуникация.

## Не использовать старые значения

Не использовать как финальные статусы:

```text
Разобрано / классифицировано
Передал закупщику
В работе / ожидание торгов
Завершение / фиксация результата
Закрыто / база / наблюдение как рабочая колонка
```

Для amoCRM использовать `active_pipeline_status` из файла `07_воронка_и_статусы_amoCRM.md`.

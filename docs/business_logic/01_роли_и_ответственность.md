# Роли и ответственность в amoCRM-логике

## Сотрудник 1 — загрузчик

Зона ответственности:

```text
загрузить файл / архив / ссылку
проверить, что документы прикреплены
не принимать решение по приоритету и маршруту
```

После загрузки карточка должна перейти к LLM-обработке.

## LLM — первичный классификатор

LLM должен заполнить:

```text
Тип ситуации
Приоритет
Направление
Подтип направления
Краткое описание карточки
Следующее действие
Дата дедлайна / срок подачи
Нужна закупка / расчёт
Нужен звонок по СОЗ
Архивное назначение LLM
Уверенность классификации
```

LLM использует ту же маршрутизацию, что и сотрудники:

```text
Р1/Р2/Р3 + СОЗ → Сотрудник 2
Р1/Р2/Р3 + реальные торги → Сотрудник 3
Неясно → Сотрудник 2
Р4 → архив / база
```

## Сотрудник 2 — продажник / квалификатор / владелец СОЗ

Зона ответственности:

```text
проверка LLM
разбор входящего потока
работа с СОЗ
звонок заказчику / площадке / контакту
уточнение даты реального торга
подтверждение или исправление маршрута
передача сомнительных кейсов закупщику
```

Сотрудник 2 отвечает за:

```text
Р1/Р2/Р3 + СОЗ
Неясно
Р3, где нужна проверка перед закупкой
архивные карточки к обзвону
```

Важно: **реальный запрос котировок / идущие торги — не его основная зона ответственности**, если карточка уже классифицирована как реальные торги.

## Сотрудник 3 — закупщик / расчётчик

Зона ответственности:

```text
расчёты
запрос КП
поставщики
сроки
закупочные цены
передача готового КП дилеру
после решения дилера — заявка в Производство 1 / 2
```

Сотрудник 3 получает:

```text
Р1/Р2/Р3 + Запрос котировок / реальные торги
карточки, которые Сотрудник 2 передал в закупку из-за сомнений
карточки, где нужен технический / закупочный расчёт
```

## Сотрудник 4 / дилер / канал продаж

Зона ответственности:

```text
получить КП и расчёты
решить: выходим / не выходим / нужно уточнить
сообщить решение Сотруднику 3
```

## Руководитель / контролёр

Зона ответственности:

```text
контроль Р1/Р2
контроль просрочек
контроль неясных и спорных классификаций
контроль архивного назначения
обучение сотрудников
ревизия архива раз в месяц
```

## Масштабирование ролей

При добавлении новой пары сотрудников не создавать независимый дубль CRM. Добавлять поля:

```text
Команда
Ответственный продажник
Ответственный закупщик
Контролёр
Направление
```

Новая пара работает через фильтр/очередь, а не через отдельную неконтролируемую доску.

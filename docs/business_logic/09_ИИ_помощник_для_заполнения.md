# ИИ-помощник для amoCRM

## Цель

LLM должен не просто классифицировать, а подготовить карточку сделки amoCRM.

## Выходной JSON

```json
{
  "title": "[Р2] СОЗ — Протон-ПМ — специнструмент — уточнить дату торгов",
  "type_situation": "СОЗ",
  "priority": "Р2 — Быстрые Деньги",
  "direction": "SPEC-DRAWING",
  "subtype": "твердосплав по чертежам",
  "customer": "ПАО Протон-ПМ",
  "procedure_number": "...",
  "deadline": "YYYY-MM-DD",
  "nmc": 0,
  "next_action": "Позвонить и уточнить дату реального торга",
  "responsible_role": "Сотрудник 2",
  "working_status": "СОЗ — звонок / уточнить дату",
  "need_procurement": false,
  "archive_destination_llm": "Архив — СОЗ / Ждём реальные торги",
  "manager_question_required": false,
  "llm_comment": "Краткое объяснение"
}
```

## Правило по СОЗ

Если тип ситуации = СОЗ, даже при Р1/Р2/Р3 владелец — Сотрудник 2.

Исключение: если есть сомнение, что это не СОЗ, Сотрудник 2 может передать в закупку / расчёт.

## Правило по реальным торгам

Если тип ситуации = Запрос котировок / реальные торги и приоритет Р1/Р2/Р3, владелец — Сотрудник 3.

## Архивное назначение

LLM предлагает архив, но итоговое назначение может подтвердить/изменить сотрудник или руководитель.

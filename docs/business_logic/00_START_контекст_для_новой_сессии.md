# START: контекст для новой сессии

Рабочий проект: CRM для тендеров RETEK.

Текущая целевая платформа: **amoCRM**.

Главная логика:

```text
LLM распознаёт файлы → создаёт/обновляет сделку amoCRM → сделка попадает в активную воронку → сотрудники двигают её по процессу → финальные карточки уходят в статус "К архивированию" → внешний микросервис переносит их в архивные воронки.
```

## Тип интеграции amoCRM

Использовать **внешнюю интеграцию**, а не приватную.

Причина: нам нужно создавать/обновлять сделки, поля, задачи, примечания, статусы и переносить сделки между воронками через API. Не нужен JS-виджет внутри интерфейса amoCRM на MVP.

## Основная воронка

`Тендеры RETEK — активная работа`

Статусы:

```text
LLM распознал
Проверка Сотрудника 2
СОЗ — звонок / уточнить дату
СОЗ — ждём реальный торг
Передано в закупку / расчёт
КП готовится
КП передано дилеру
Решение дилера
Передано в производство
К архивированию
```

## Архивные воронки

Рекомендуемые:

```text
Архив — направления
Архив — СОЗ / развитие
```

Архив не является удалением. Сделка переводится в другую воронку через изменение `pipeline_id` и `status_id`.

## Маршрутизация

```text
Р1/Р2/Р3 + СОЗ → Сотрудник 2
Р1/Р2/Р3 + Запрос котировок / реальные торги → Сотрудник 3
Неясно → Сотрудник 2, возможна передача Сотруднику 3
Р4 → Наблюдаем / В базу / Архив
```

## Направления классификатора

Крупное направление:

```text
SPEC-DRAWING — специнструмент по чертежам / ТЗ
```

Подтипы:

```text
твердосплав по чертежам
быстрорез по чертежам
алмазный по чертежам
прочий инструмент по ТЗ / образцу / эскизу
```

## Главный принцип

> В активной воронке остаётся только карточка, по которой есть следующее действие.

Если действия нет — дата возврата или архив.

# XMind outline — алгоритм распределения заявок

## 1. Загрузка
- Сотрудник 1
  - Загружает файлы
  - Не классифицирует
  - Не ставит приоритет

## 2. LLM-разбор
- Распознать документы
- Извлечь данные
  - Заказчик
  - Тип процедуры
  - Срок
  - НМЦ
  - Лоты
  - Предмет закупки
- Определить тип ситуации
  - СОЗ
  - Запрос котировок / реальные торги
  - Неясно
  - Р4 / база
  - Не наш ассортимент
- Поставить приоритет
  - Р1 — Срочно
  - Р2 — Быстрые Деньги
  - Р3 — Средние Деньги
  - Р4 — Наблюдаем / В базу

## 3. Проверка Сотрудника 2
- Проверить LLM
- Исправить ошибки
- Подтвердить тип ситуации
- Подтвердить приоритет

## 4. Главное правило маршрутизации
- Р1 / Р2 / Р3 + СОЗ
  - Ответственный: Сотрудник 2
  - Действие: позвонить
  - Вопрос: на какую дату будет реальный торг?
- Р1 / Р2 / Р3 + Запрос котировок / реальные торги
  - Ответственный: Сотрудник 3
  - Действие: закупка / расчёт / КП
- Неясно
  - Ответственный: Сотрудник 2
  - Действие: проверить тип процедуры
  - Возможное действие: передать Сотруднику 3
- Р4
  - Наблюдаем / В базу
- Не наш ассортимент
  - Закрыто

## 5. Сотрудник 3
- Получает реальные торги Р1/Р2/Р3
- Получает спорные случаи от Сотрудника 2
- Делает расчёт
- Готовит КП
- Передаёт КП дилеру

## 6. Сотрудник 4 / Дилер
- Получает готовое КП
- Решает
  - Выходим
  - Не выходим
  - Нужно уточнить
  - Ждём

## 7. Производство 1 / 2
- Если дилер решил "Выходим"
  - Сотрудник 3 передаёт заявку в производство
- Затем карточка закрывается или уходит на контроль результата

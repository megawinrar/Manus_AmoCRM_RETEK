# PATCH4 — переход логики CRM на amoCRM + архивные воронки

Дата: 2026-06-07

Этот патч переписывает рабочую концепцию с Airtable/Odoo-логики на amoCRM.

Главное изменение: CRM рассматривается как **операционный канбан активной работы**, а архив — как отдельная управляемая база будущей проработки и аналитики.

## Зафиксированные решения

1. Основная CRM-платформа для дальнейшей реализации: **amoCRM**.
2. Тип интеграции: **внешняя интеграция amoCRM**, не приватная интеграция.
3. Основная сущность: **сделка amoCRM = тендерная возможность / заявка / СОЗ / реальный торг**.
4. Активная воронка не должна хранить весь исторический мусор.
5. Последний статус активной воронки: **К архивированию**, а не полноценный архив.
6. Перенос из активной воронки в архив выполняет внешний микросервис по расписанию.
7. Архив — это не удаление и не конец, а база будущей работы, обзвонов, возвратов и аналитики.
8. Масштабирование сотрудников делается через поля `Команда`, `Ответственный продажник`, `Ответственный закупщик`, `Направление`, а не через дублирование досок.

## Ключевое правило активной CRM

> В активной воронке живёт только то, по чему есть следующее действие.

Если следующего действия нет, карточка должна уйти либо в ожидание с датой возврата, либо в архив с причиной закрытия.

## Основная маршрутизация

```text
Р1/Р2/Р3 + СОЗ → Сотрудник 2 / продажник / квалификатор
Р1/Р2/Р3 + Запрос котировок / реальные торги → Сотрудник 3 / закупщик / расчётчик
Неясно → Сотрудник 2, может передать Сотруднику 3
Р4 → Наблюдаем / В базу / Архив
```

## Новая логика направлений

Объединено крупное направление:

```text
SPEC-DRAWING — специнструмент по чертежам / ТЗ
```

Внутри него подтипы:

```text
твердосплав по чертежам
быстрорез по чертежам
алмазный по чертежам
прочий инструмент по ТЗ / эскизу / образцу
```

Причина: для CRM это один бизнес-процесс — требуется техническая оценка, расчёт, производство, сроки и коммуникация.

## 1. Что было важно в этой сессии

Мы не просто классифицировали тендеры в чате. Мы начали превращать каждый разбор в обучающий пример:

```text
сырой тендер → реальные позиции товара → признаки → правильный код глоссария → P1/P2/P3/P4 → действие в CRM → правило для будущей LLM
```

Новая модель не должна учиться только по финальному выводу. Ей нужно видеть **сырые позиции**, потому что именно по ним исправлялись ошибки.

## 3. Исправления ошибок, которые нельзя забыть

### 3.1. Пластины ≠ плашки

Это была критическая ошибка.

```text
Пластины — сменные режущие пластины для токарного/фрезерного инструмента.
Плашки — резьбонарезной инструмент.
```

Если в тендере **пластины KOBI** и **аналоги не допускаются**, это:

```yaml
glossary_code_primary: INSERT-01
glossary_code_secondary: ""
priority: P4 по умолчанию
priority_exception: P3 только если есть точный канал поставки KOBI
```

Запрещено ошибочно ставить:

```text
HSS-01
HSS-02
HSS-07
CARB-02
"плашки"
"подобрать аналог"
```

Если аналоги не допускаются — не подбирать замену. Проверять только точный бренд / точные каталожные номера.

---

### 3.2. INSERT-03 не дробить на компоненты

Для сборной брендовой заявки одного производителя, например Walter, где внутри пластины, державки, винты, сверла, фрезы, метчики, срабатывает общий маршрут:

```yaml
glossary_code_primary: INSERT-03
glossary_code_secondary: ""
```

Компоненты можно сохранить только как состав заявки, но не как вторичные маршруты классификации.

Нельзя превращать INSERT-03 в набор:

```text
INSERT-01 + INSERT-02 + HSS-01 + HSS-02 + CARB-02
```

---

### 3.3. ПП РФ №1875 / национальный режим не всегда означает запрет аналогов

Нужно читать карточку закупки.

Если указано:

```text
эквивалент допускается
и/или запрет не применяется по подп. «и» п. 5 / пункту 4 постановления №1875
```

то это **не** сценарий "точный бренд без аналогов".

В таких случаях можно классифицировать как обычный подбор технически соответствующего аналога, например:

```text
CARB-02 для твердосплава
HSS-05 для брендовых HSS-фрез
```

Если явно написано:

```text
эквивалент не допустим
аналоги не допускаются
```

тогда подбор аналога запрещён.

---

### 3.4. Primary code в смешанных тендерах выбирать не по количеству строк

Если тендер смешанный, нельзя выбирать primary только по числу позиций или штук.

Приоритет выбора:

```text
1. Явное правило глоссария, если оно есть.
2. Коммерческая масса / НМЦ товарной группы.
3. Критический бизнес-интерес.
4. Только потом количество строк или штук.
```

Но если это INSERT-03, KOBI/no analog, DIAM-01 или другой специальный маршрут, не дробить по формальному количеству.

---

### 3.5. Приоритет должен быть одним значением

Не писать в поле `priority` двойные формулировки вроде:

```text
P1, если КП ещё нет; базовый P3
```

Правильно:

```yaml
priority: P1 Срочно
base_priority_without_close_deadline: P2
```

P1 ставить, если:

```text
срок подачи заявок близко / горит
и КП ещё не готово
или нужно срочно передать закупщику для расчёта
```

Если срок не найден — не выдумывать срок и не ставить P1 только по ощущению.

---

### 3.6. HSS без ГОСТ может быть очень интересным

Не все HSS — P4.

Если это:

```text
HSSCo8 / HSSCo5 / HSSE-PM
брендовая линейка
без прямого ГОСТ
допускается эквивалент
много позиций / высокая НМЦ
```

то это коммерчески интереснее обычных ГОСТ-сверл/метчиков.

Пример: ZPS-FN у КБП:

```yaml
glossary_code_primary: HSS-05
glossary_code_secondary: HSS-07
priority: P1 Срочно
base_priority_without_close_deadline: P2
```

## 4. Итоговые обучающие примеры и правильные маршруты

### 4.1. Gesac / твердосплавные концевые фрезы

```yaml
code: CARB-02
priority: P2
rule: "Каталожные твердосплавные фрезы с допуском эквивалента и без жёсткого ГИСП/ЕПОЗ → CARB-02/P2. Если срок горит и КП нет → P1."
```

### 4.2. Омсктрансмаш / многолотовая закупка

```yaml
lot_1:
  subject: "метчики ГОСТ"
  code: HSS-02
  priority: P4
lot_2:
  subject: "сверла Р6М5/ВК8, крупные диаметры"
  code_primary: HSS-01
  code_secondary: HSS-07
  priority: P3
rule: "Многолотовые закупки классифицировать по каждому лоту отдельно."
```

### 4.3. ЧТЗ-УРАЛТРАК / борфрезы ВК10-ХОМ

```yaml
code: CARB-06
priority: P2
rule: "Борфрезы ВК10/ВК10-ХОМ с допуском аналога и без жёсткого ГИСП/ЕПОЗ → CARB-06/P2."
```

### 4.4. Исток / Walter / сборная брендовая заявка

```yaml
code: INSERT-03
priority: P3
rule: "Сборная брендовая заявка одного производителя не дробится на INSERT/HSS/CARB-компоненты."
```

### 4.5. ОНИИП / KOBI / пластины без допуска аналогов

```yaml
code: INSERT-01
secondary: ""
priority: P4
priority_exception: "P3 только при наличии точного канала KOBI"
rule: "Пластины KOBI без допуска аналогов → INSERT-01. Не путать с плашками. Не подбирать аналоги."
```

Старая ошибочная логика `HSS-mix / плашки / HSS-01/HSS-02/HSS-07` отменена и не должна использоваться.

### 4.6. РПЗ / алмазный инструмент по чертежам

```yaml
code: DIAM-01
priority: P3
rule: "Алмазные фрезы, сверла, фасочники, круги по чертежам заказчика → DIAM-01. Не CARB, не HSS, не INSERT."
```

Если это запрос КП без НМЦ — P3. Если реальная процедура и есть канал производства — P2. Если финальная процедура горит и КП нет — P1.

### 4.7. ОКБ Факел / твердосплавные сверла и микросверла

```yaml
code: CARB-02
priority: P2
rule: "Твердосплавные сверла/микросверла без бренда, без чертежа, без ГИСП/ЕПОЗ → CARB-02/P2."
```

ПП РФ №1875 не равен автоматическому запрету аналогов, если запрет не применяется по исключению.

### 4.8. КБП / ZPS-FN / HSS-фрезы без ГОСТ

```yaml
code_primary: HSS-05
code_secondary: HSS-07
priority: P1 Срочно
base_priority_without_close_deadline: P2
submission_deadline: "08.06.2026 16:00 (+03:00)"
contacts:
  placement_contact: "Смирнов Александр Сергеевич, a.smirnov@npovk.ru"
  organizer_contact: "Гайдай Дарья Михайловна, d.gayday@npovk.ru"
```

Правило:

```text
Каталожные брендовые фрезы ZPS-FN из HSS/HSSCo/HSSE-PM с допуском эквивалента → HSS-05.
Если широкий состав фрез, крупные диаметры или высокая НМЦ → HSS-07 secondary.
Если срок подачи горит → P1.
Без горящего срока это P2, не P3 и не P4.
```

## 5. Мини-чеклист перед выдачей ответа по новому тендеру

Перед финальной классификацией новая модель должна проверить:

```text
1. Это реальная закупка или запрос КП / СОЗ?
2. Есть ли срок подачи заявок? Если есть — записан ли он отдельным полем?
3. Есть ли контакты? Если есть — записаны ли ФИО/email/телефон?
4. Это один лот или несколько? Если несколько — классифицированы ли лоты отдельно?
5. Есть ли запрет аналогов или эквивалент допускается?
6. ПП №1875 действительно запрещает аналоги или там есть исключение?
7. Не перепутаны ли пластины и плашки?
8. Не сработал ли специальный маршрут: INSERT-03, DIAM-01, KOBI/INSERT-01?
9. Для смешанного лота primary выбран по правилу/НМЦ/коммерческой массе, а не по числу строк?
10. В поле priority стоит одно значение, а не условная фраза?
11. В обучающий пример сохранены реальные сырые позиции товара?
12. Новое правило добавлено в глоссарий только если оно действительно обобщаемое?
```

## 6. Как начать новую сессию

В новую сессию лучше отправить архив и написать:

```text
Продолжаем проект Odoo CRM по тендерам. Используй архив как основной контекст.
Сначала прочитай 00_START_контекст_для_новой_сессии.md, затем 14_HANDOFF_new_session.md.
Сейчас мы продолжаем тренировать LLM-глоссарий для классификации тендеров.
Особенно учитывай исправления: сроки и контакты обязательны, пластины ≠ плашки, KOBI/no analog = INSERT-01, Walter-mix = INSERT-03, diamond drawings = DIAM-01, ZPS-FN HSS без ГОСТ = HSS-05/P1 при горящем сроке.
```

## 7. Что делать при следующем тендере

Для каждого нового тендера:

```text
1. Вытащить реквизиты закупки.
2. Вытащить сроки и контакты.
3. Вытащить реальные позиции товара.
4. Определить признаки: материал, ГОСТ/без ГОСТ, бренд, чертеж, эквивалент, запреты, НМЦ, количество.
5. Дать классификацию в YAML.
6. Добавить пример в 12_тренировка_LLM_классификатора.md.
7. Добавить JSONL-запись в 13_llm_training_examples.jsonl.
8. Добавить новое правило в 06_глоссарий_и_правила_классификации_LLM.md, если правило новое.
9. Добавить запись в 99_CHANGELOG.md.
10. Вернуть обновлённый архив.
```

## 4. Дополнительная фиксация 2026-06-06B: новые кейсы и бизнес-стоп-фильтр

### 4.1. Важно: зуборезный HSS должен идти по старому коду HSS-08

В архиве уже существует код:

```yaml
HSS-08: "Зуборезный быстрорежущий инструмент"
```

Поэтому новые кейсы:

```yaml
Долбяки ГОСТ 9323-79: HSS-08 primary, HSS-07 только context
Фрезы червячные ГОСТ 9324-2015: HSS-08 primary, HSS-07 только context
```

Не записывать долбяки и червячные фрезы как `HSS-01`. Не делать `HSS-07` основным кодом, если сработал более точный маршрут `HSS-08`.

### 4.2. Малые зенковки

```yaml
Малые зенковки из быстрорежущей стали без бренда/чертежей/специсполнения: HSS-01, P4, база.
```

### 4.3. Бизнес-стоп-фильтр по пластинам и державкам

Пользователь подтвердил: компания не торгует пластинами и державками.

Если основная масса лота:

```text
сменные пластины, державки, корпуса под СМП, опорные пластины, втулки, рычаги, винты, комплектующие Pramet/Dormer-Pramet/Walter/Sandvik/Iscar/Seco
```

то итог:

```yaml
glossary_code_primary: "OUT_OF_SCOPE"
technical_code_for_context_only: "INSERT-03, если нужно объяснить состав"
priority: "P4 / отказ по профилю"
crm_status: "Закрыто / не наш ассортимент / не участвуем"
need_supplier_quote: false
```

Не рекомендовать брать такие лоты в работу из-за бренда или срочного срока. P1 не ставить, если сработал стоп-фильтр.

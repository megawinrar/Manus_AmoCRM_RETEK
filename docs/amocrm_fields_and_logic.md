## Обязательная маршрутизация

```text
Р1/Р2/Р3 + СОЗ → Сотрудник 2
Р1/Р2/Р3 + Запрос котировок / реальные торги → Сотрудник 3
Неясно → Сотрудник 2, может передать Сотруднику 3
Р4 → К архивированию
```

## Микросервис

Функции:

```text
сканировать Яндекс.Диск (/ТОРГИ) на новые тендеры
классифицировать тендер через LLM (Яндекс GPT)
создать сделку из результатов LLM
обновить сделку
создать задачу
добавить примечание
перенести сделку между воронками
контролировать просрочки
архивировать сделки (ночной cron)
определить архивное назначение через LLM
возвращать сделки / создавать задачи по дате возврата
```

## Яндекс.Диск

```text
Корневая папка: /ТОРГИ
Структура: /ТОРГИ/{DD.MM.YYYY}/{название тендера}/{файлы или подпапка}
Опрос: каждый час (:30)
Дедупликация: SQLite (data/processed_tenders.db)
Объём: 10–20 тендеров/день
```

## LLM-сервис (3 действия)

```text
Действие 1 — Классификация:
  Триггер: новая папка на Яндекс.Диске
  Результат: приоритет, направление, тип ситуации, заказчик
  Действие: создать сделку в amoCRM

Действие 2 — Архивное назначение:
  Триггер: ночной cron (02:00)
  Условие: карточка в «К архивированию» + заполнены «Причина закрытия» + «Дата возврата»
  Результат: определить куда перенести (архивная воронка + статус)
  Действие: перенести сделку в архив

Действие 3 — Распознавание из чата (будущее):
  Триггер: новая заметка в ленте карточки
  Результат: предложить статус, ждать подтверждения сотрудника

Модель: Яндекс GPT (yandexgpt/latest)
RAG: CONTEXT_FULL.md + amocrm_fields_and_logic.md как system prompt
Режим: training → production
```

## Не делать на MVP

```text
приватную интеграцию с JS-виджетом
ручное дублирование досок
хранение всего архива в последней колонке активной воронки
векторную базу (ChromaDB) — пока хватает context-injection
```

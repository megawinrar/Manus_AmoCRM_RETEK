## Slide 2: О компании и задаче
**Заголовок:** RETEK торгует режущим инструментом через тендерные площадки
**Содержание:**
- Компания RETEK — поставщик режущего инструмента (специнструмент по чертежам, HSS/ГОСТ, твердосплав, алмазный)
- Основной канал продаж — государственные и коммерческие тендеры
- Задача: построить CRM-систему, которая автоматизирует классификацию, маршрутизацию и архивирование тендерных возможностей
- Платформа: amoCRM с внешней интеграцией через API

---

## Slide 3: Главная логика системы — от файла до архива
**Заголовок:** Сквозной процесс: LLM → amoCRM → Микросервис
**Содержание:**
- Сотрудник загружает файл/ссылку с тендерной площадки
- LLM автоматически распознаёт и классифицирует тендер (тип, приоритет, направление)
- Создаётся сделка в активной воронке amoCRM с заполненными полями
- Сотрудники двигают сделку по процессу (квалификация → расчёт → КП → решение)
- Завершённые сделки уходят в статус «К архивированию»
- Микросервис-архиватор переносит их в архивные воронки по правилам

---

## Slide 4: Роли в системе — кто за что отвечает
**Заголовок:** 7 ролей обеспечивают полный цикл обработки тендера
**Содержание:**
- **Сотрудник 1 (Загрузчик)** — загружает файлы и ссылки, не принимает решений
- **LLM (Классификатор)** — заполняет тип, приоритет, направление, дедлайн, маршрут
- **Сотрудник 2 (Продажник/Квалификатор)** — проверяет LLM, ведёт СОЗ, звонит заказчикам
- **Сотрудник 3 (Закупщик/Расчётчик)** — расчёт себестоимости, КП, работа с поставщиками
- **Сотрудник 4 / Дилер** — принимает решение «выходим / не выходим» на торги
- **Руководитель** — контроль Р1/Р2, просрочки, ревизия архива раз в месяц
- **Микросервис-архиватор** — автоматический перенос, контроль просрочек, задачи на возврат

---

## Slide 5: Маршрутизация — кому попадает тендер
**Заголовок:** Приоритет + тип ситуации определяют маршрут сделки
**Содержание:**
- **Р1/Р2/Р3 + СОЗ** → Сотрудник 2 (продажник) — звонок, уточнение даты реального торга
- **Р1/Р2/Р3 + Реальные торги** → Сотрудник 3 (закупщик) — расчёт, КП, поставщики
- **Неясно** → Сотрудник 2, может передать Сотруднику 3 после проверки
- **Р4 (Наблюдаем)** → сразу в архив / базу без активной работы
- Приоритеты: Р1 — Срочно, Р2 — Быстрые Деньги, Р3 — Средние Деньги, Р4 — В базу

---

## Slide 6: Активная воронка — 10 статусов процесса
**Заголовок:** Воронка «Тендеры RETEK» ведёт сделку от распознавания до архива
**Содержание:**
- 1. LLM распознал — тендер только поступил, LLM заполнил поля
- 2. Проверка Сотрудника 2 — человек проверяет классификацию LLM
- 3. СОЗ — звонок / уточнить дату — нужен звонок по сбору заявок
- 4. СОЗ — ждём реальный торг — дата известна, ждём
- 5. Передано в закупку / расчёт — закупщик считает
- 6. КП готовится — формируется коммерческое предложение
- 7. КП передано дилеру — дилер получил расчёт
- 8. Решение дилера — ждём ответ: выходим / не выходим
- 9. Передано в производство — заявка подана, идёт работа
- 10. К архивированию — сделка завершена, ждёт переноса

---

## Slide 7: Архивные воронки — база будущей работы
**Заголовок:** Архив — это не мусорная корзина, а управляемая база аналитики и возвратов
**Содержание:**
- **Архив — направления** (по типу инструмента): Специнструмент по чертежам, HSS ГОСТ, Твердосплав, Алмазный, Не наш ассортимент
- **Архив — СОЗ / развитие** (по действию): Ждём реальные торги, К обзвону, Повторить через 30 дней, Повторить через 90 дней
- Каждая архивная карточка имеет: причину закрытия, дату возврата или обоснование «почему больше не трогаем»
- Ежемесячная ревизия руководителем: карточки без даты, без причины, СОЗ без возврата

## Slide 8: Направления и классификация инструмента
**Заголовок:** 8 направлений классификации покрывают весь ассортимент RETEK
**Содержание:**
- **SPEC-DRAWING** — специнструмент по чертежам / ТЗ (подтипы: твердосплав, быстрорез, алмазный, прочий)
- **HSS-STANDARD** — стандартный быстрорез / ГОСТ
- **CARBIDE-STANDARD** — стандартный твердосплав
- **DIAMOND-STANDARD** — алмазный инструмент стандартный
- **SOZ-DEVELOPMENT** — СОЗ / развитие / будущий торг
- **REAL-TENDER** — реальные торги / запрос котировок
- **OUT-OF-SCOPE** — не наш ассортимент
- **ARCHIVE-LEAD** — база / наблюдение / будущая проработка

## Slide 9: 33 пользовательских поля сделки
**Заголовок:** Каждая сделка содержит 33 поля для полного контроля тендерного процесса
**Содержание:**
- **Идентификация:** Внешний ID, Источник, Ссылка на площадку, Заказчик, ИНН, Номер процедуры
- **Классификация:** Тип ситуации, Тип процедуры, Приоритет, Направление, Подтип направления
- **Финансы и сроки:** НМЦ, Срок подачи, Дата следующего действия
- **Ответственность:** Продажник, Закупщик, Команда, Дилер/канал продаж
- **Процесс:** Нужна закупка, Сомнения СОЗ/реальные торги, Статус КП, Решение дилера, Производство
- **Архив:** Причина закрытия, Архивное назначение LLM, Архивное назначение итоговое, Дата возврата
- **LLM:** confidence, comment, Manager comment

## Slide 10: Микросервис-архиватор — автоматизация рутины
**Заголовок:** Микросервис выполняет 8 ключевых функций без участия человека
**Содержание:**
- Создать сделку из JSON, полученного от LLM
- Обновить сделку (поля, статус, ответственный)
- Создать задачу для сотрудника
- Добавить примечание к сделке
- Перенести сделку между статусами
- Перенести сделку в архивную воронку (по правилам маршрутизации)
- Проверить просрочки (cron hourly) — Р1/Р2 без действия, зависшие сделки
- Создать задачу на дату возврата из архива

## Slide 11: Правило активной CRM и масштабирование
**Заголовок:** В активной воронке живёт только то, по чему есть следующее действие
**Содержание:**
- Если следующего действия нет — дата возврата или архив с причиной закрытия
- Масштабирование: новые сотрудники добавляются через поля «Команда», «Ответственный продажник», «Ответственный закупщик», «Направление»
- Не создавать дубли досок — работать через фильтры и очереди
- amoCRM API: 7 req/s на интеграцию, 50 req/s на аккаунт
- Интеграция: внешняя (OAuth), долгосрочный JWT-токен, автообновление через refresh_token
